|---|---|---|

| 登录方式 | **仅 GitHub / Linux.do**，不支持邮箱 | 多源 |

### 1.2 领取步骤

1. 打开 <https://agentrouter.org/register>（有邀请码就带 `?aff=XXXX`）
2. 用 GitHub 或 Linux.do 登录
3. 左侧栏「API 令牌」→ 添加令牌（**有"无限额度"选项，勾上**）→ 复制 Key
4. 配置环境变量：
   ```powershell
   $env:ANTHROPIC_BASE_URL = "https://agentrouter.org"
   $env:ANTHROPIC_AUTH_TOKEN = "<你的 Key>"
   # OpenAI 兼容端点
   $env:OPENAI_BASE_URL  = "https://agentrouter.org/v1"
   ```
5. **每天回后台首页点签到**，领 $25

### 1.3 你已经踩过的坑（实测，都是本机真实报错）

| 报错 | 含义 | 怎么办 |
|---|---|---|
| `402 Budget pool quota has been exhausted` | 该模型的**预算池空了** | 换模型（`gpt-6.1-sol` / `gpt-5.6-sol` 实测可用），或等下一批 |
| `503 no available channel ... 无可用渠道` | 该模型**当前没有渠道** | 换模型 |
| `exceeded retry limit, last status: 429` | 该 key 被限流 | 等，或切到另一个站 |

> 💡 **本机实测记录（2026-11-11）**：
> agentrouter 的 `gpt-6-astra` 一度 402（预算池空），但**当天晚些时候又恢复了**——
> 同一个模型、同一个 key，早晚可用性不同。**别因为一次 402 就判定这个站废了。**
> 你的 `relay-agentrouter` 和 `relay-agentrouter-sol` 两个 profile 就是为这个准备的。

## 3. All API Hub —— 自动签到的主力（推荐先装这个）

> 官方商店：<https://chromewebstore.google.com/detail/lapnciffpekdengooeolaienkeoilfeo>
> 本机状态：**未安装**（已查 `AppData/Local/Google/Chrome/User Data/Default/Extensions/`，无此 id）

### 3.1 为什么它是首选

| 能力 | 说明 |
|---|---|
| **自动签到** | 每个站每天自己登、自己点签到 |
| 余额总览 | 一个面板看所有站的余额与用量 |
| 价格对比 | 同一个模型哪家便宜 |
| 密钥导出 | 不用手抄 |

### 3.2 装之前必须知道的三件事

1. **先在同一个 Chrome 里登录过那个站**，否则扩展没有登录状态可用
   （Edge 登录的，Chrome 里看不到）
2. **它握着你的全部凭证** —— 只从官方商店装，别装"绿色版/破解版"
3. **浏览器关着当天就不会签** —— 它的定时任务依赖浏览器运行

### 3.3 关键设置（这一步决定了会不会被限流）

```
设置 → 签到与兑换 → 自动签到
  □ 调度模式 → 选「随机时间」，不要选「固定时间」
    （固定时间的话所有用这个插件的人都在同一秒打同一个站，服务器会卡）
  □ 时间窗开始/结束 → 设成你清醒的时段（如 09:00–22:00）
```

装完点「立即运行」试一次，第二天看余额有没有涨。

> 🔒 **安全提醒**：这个扩展类别曾出过事 —— 赛门铁克调查发现大量 Chrome 扩展硬编码
> API 密钥（影响 2000 万+ 用户）；Socket 披露过伪装成交易工具、
> 偷取 MEXC API 密钥并回传 Telegram 的恶意扩展（MEXC API Automator）。

## 4. magpie —— 多站统一管理 + 自动签到 + 自动换卡

> 项目：<https://github.com/yetone/magpie> · 安装：`curl -fsSL https://usemagpie.ai/install.sh | sh`
> 本机状态：**未安装**（`command -v magpie` 无结果）
> ⚠️ 注意：另有一个同名的「Magpie 浏览器扩展」（隐私收藏夹工具），**与本项目无关**，别搞混。

### 4.1 它解决什么

你手上有 12 条线（29 个 CLI 预设 / 10 个上游），问题不是缺站，是**缺统一管理**。
magpie 把它们收进一个面板，并且能：

| 能力 | 细节 |
|---|---|
| **一键整体切换** | `magpie save 工作台` / `magpie use 摸鱼`，一条命令全换 |
| **12 种路由策略** | smart / order / rotate / usage / pace 等，可组合 |
| **额度耗尽自动换** | 建一个路由组，把同一家站的多张卡合成一个 |
| **自动签到** | `magpie accounts checkin` |
| **插件钩子** | `auth.checkin` —— magpie 按北京日自动为每个账号签到一次 |

### 4.2 自动签到机制（源码级）

- 插件通过 HTTP 端点报告状态：
  `POST /v1/daily-sign/status {username}` → 已签返回 `done`
  `POST /v1/daily-sign {username}` → 未签返回 `claimed`
- **24 小时冷却由服务端控制**，重复调用只会返回 `done`
- 签到状态缓存 60 秒，签到成功后主动清缓存
- 界面入口：Settings › Usage › warm-up and check-in
- 第三方插件示例：`codar-magpie`（npm 包）

### 4.3 导入你已有的线路

```bash
magpie provider import cc-switch     # 从 CC Switch 导
magpie provider import claude-code   # 从 Claude Code 导
magpie provider import codex         # 从 Codex 导
magpie accounts discovery on         # 把已登录的订阅账号变成 provider
```

> ⚠️ **本机实况**：magpie 二进制**没装在这台 Windows 上**（全盘搜索只命中我自己的临时文件），
> `where magpie` 也没有。**你截图里那套 magpie 很可能在另一台机器或另一个环境。**
> 要确认就在跑 magpie 的那台机器上执行 `magpie --version`，
> 再按源码规则找它的配置目录（见总手册 §3.2）。

### 4.4 已知坑（issue #1518）

开机自启动时 magpie 早于代理启动，会直连失败去读额度 →
**在设置里填明确的代理地址**（已在 v0.1.1169 修复）。

## 5. free-claude-code (FCC) —— 61 家模型的"万能插座"

> 项目：<https://github.com/Alishahryar1/free-claude-code> ·
> [深入评测](https://aicoderscope.com/blog/free-claude-code-open-source-review-2026) ·
> [中文解读](https://alishangtian.com/article/user-fe20a34a8b)
> 本机状态：**未安装**
> 许可：AGPL-3.0，**与 Anthropic 无关，未获官方背书**

### 5.1 它是什么

本地代理 + Admin UI，跑在 `127.0.0.1:8082`，
把编码智能体和模型供应商之间做成"万能插座"：

| 数字 | 值 |
|---|---|
| 供应商 | **61 家**（托管 / 订阅 / 付费 / 免费层 / 本地） |
| 支持的智能体 | **11~12 个**（Claude Code、Codex、OpenCode、Cline、Aider、VS Code Chat…） |
| 免费 token | 宣称 **1.3B+ / 月** |
| Star | 3 万+（上线一周 1.7 万） |

### 5.2 杀手功能：自动换卡

**请求失败（额度耗尽/限流/宕机）时自动切到下一个模型，且不中断当前这一轮。**

这正是你"额度用完就切站，但不想中断对话"的需求的通用解：

```bash
# 配置
MODEL=<主模型>
# Model Config 里配一个有序的 "Fallback Models" 列表
# 每个 fallback 可以单独指定 reasoning effort 和 API key
```

**警告（README 原文）**："A failed request may reach and consume usage from
more than one provider before succeeding." —— 失败会消耗多个供应商的额度。

### 5.3 安装

```powershell
$s = irm "https://raw.githubusercontent.com/Alishahryar1/free-claude-code/main/scripts/install.ps1"
[scriptblock]::Create($s) | iex
```

然后 `fcc-server`（Admin UI 自动打开）→ 加 key 或连 OAuth → 选模型 Apply →
用 `fcc-claude` / `fcc-codex` 启动。

### 5.4 明确的免费模型（README 标注）

```
open_router/openrouter/free
zenmux/deepseek/deepseek-v4-flash-free
kilo/kilo-auto/free
tokenrouter/moonshotai/kimi-k3-free
nararoute/kimi-k3-free
orcarouter/deepseek/deepseek-v4-flash-free
xkiro/qwen/qwen3.7-flash:free
```

本地：`Ollama` / `llama.cpp` / `LM Studio`

### 5.5 ⚠️ 期望要放对

免费路径主要跑**开放权重模型**（如 Nemotron），**不是真正的 Claude 模型**。
要用真 Claude，Anthropic 的 $20/月 Pro 仍是底线。
另外免费额度"看天吃饭"，**限额是主要痛点** —— FCC 解决的正是这个。

## 8. 落地顺序（建议）

```
第 1 步  装 All API Hub 扩展，把已有的 AgentRouter / pincar 加进去
         → 每天自动签到，先把手上两条线的额度吃满

第 2 步  按 §6 表再开 2~3 个站（优先 AnyRouter / KKtoken / DoCode，
         都是"两者都支持"且日签到 $20~25）
         → 容量从 2 站变 5 站

第 3 步  需要"一个面板管理所有 + 自动换卡"时，再装 magpie
         → magpie provider import codex / claude-code / cc-switch
         → 建路由组，把同家的多张卡合成一个，额度耗尽自动切

第 4 步  想要 61 家模型随便换、且完全本地，再考虑 FCC
         → 它是本地代理，跑 8082，fcc-claude / fcc-codex 启动
```

> 🔁 **第 1 步和第 3 步是互补的，不是替代。**
> All API Hub 负责"把额度每天领到手"，magpie 负责"领到的额度怎么用得聪明"。
> 但你**已经有两条线在跑了**，所以第 1 步优先 —— 先把现有的签到自动化，
> 成本最低、见效最快。
