>

## 能力线 1 · 让 AI 的产出可被机器验收（而不是"看起来不错"）

### 问题
你让 Codex 写一课，它写完了。**但"写完了"不是"对了"。**
你自己的实验就是这么翻车的：best.psnr 精确停在 fork 点、伪标签误差 99.4%
——那些数字在跑完之前看着都很正常。

### 解法：每类产出配一个**能被执行**的闸

| 产出类型 | 闸 | 你已有的 |
|---|---|---|
| C 语言课程 | 每个代码块 `gcc -std=c11 -Wall -Wextra` 编译 + 占位符检查 + `volatile` 检查 | ✅ `verify.py`（16 项断言自测通过） |
| 实验 | 结果必须带轮次/父点/`test-informed` 标签，缺一不许写进 README | ✅ `registry\EXPERIMENT_REGISTRY_*.md` 的字段约定 |
| 文档 | 链接可达、命令可执行（不写"运行 xxx 命令"却不说 xxx 是什么） | ❌ **待建** |
| 配置 | JSON 无 BOM、变量都能解析、备份存在 | ✅ `connect_local_models.py` 的读回断言 |
| Git 操作 | 分支名合规、不碰禁区文件、提交信息合规 | ❌ **待建（钩子）** |

### 手上要做的（30 分钟）

把 `verify.py` 变成**提交前的自动检查**，而不是你想起来才跑：

```bash
# .git/hooks/pre-commit （Windows: core.hooksPath）
#!/bin/sh
python "/c/Users/18798/Documents/技术蒸馏课程/99_工具与模板/verify.py" --staged
```

再进一步：放进 `.github/workflows/`（第 4 周任务 4.1），**让 CI 当第二个人**。

> ⭐ **判断标准**：一个闸如果需要你"记得跑"，它迟早会漏。
> **把闸挂到提交动作上。**

## 能力线 2 · 一份知识，两个 agent 共用（消除重复劳动）

### 问题

但**Codex 侧的 skills 没开**（`~/.codex/config.toml` 的 `[features]` 里没有 `skills = true`）。
现在你在 Claude Code 里写的东西，Codex 看不见。

### 解法

```toml
# ~/.codex/config.toml

```

```powershell
New-Item -ItemType Junction -Path "C:\Users\18798\.codex\skills" -Target "C:\Users\18798\.claude\skills"
```

> ⚠️ **必须用 Junction，不能用 `ln -s`** —— 我实测过 Git Bash 的 `ln -s` 在 Windows 上
> 会落成**实体副本**，正本改动不同步（已记入 memory）。

## 能力线 3 · 把"研究"变成可复现的流水线（而不是一次性问答）

### 问题
你做深度研究（论文综述、实验方案）时，
产出散落在会话里；换一次会话，**上下文就没了**。

### 解法：**四层记忆分层**

```
第 4 层  产物      README / 论文 / 实验注册表     ← 能给别人看的
第 3 层  决策      DECISIONS.md（为什么这么选）    ← 半年后你会忘
第 2 层  事实      registry/*.md（数字+轮次+标签）  ← 机器可查
第 1 层  环境      memory/*.md（坑、固定流程）      ← 你的"开机手册"
```

> ⭐ **你自己已经踩过这个坑并写下来了**：
> memory 里那条「开工前必读记忆索引」—— 根因就是"自己写的文档不能当依据，
> 得读 MEMORY.md 的最新条目"。**这就是第 3 层缺失的证据。**

### 每个新项目开坑时必做的 4 件事（20 分钟）

```bash
mkdir -p 项目根/{docs,registry,decisions}
# 1. README.md        —— 一句话说清楚这项目在干什么 + 精确入口命令
# 2. decisions/DECISIONS.md —— 每条决策写：为什么选 A 不选 B + 什么条件下推翻它
# 3. registry/EXPERIMENT_REGISTRY.md —— 表头固定：ID|父点|轮次|数据|指标|标签
# 4. 一个 STATUS.md，只写"当前状态"，历史进 docs/ 且只保留最近一节
```

**DECISIONS.md 的模板**（每条 5 行就够）：

## 能力线 4 · 排产与资源调度（你的独有优势，别浪费）

### 问题
你有三台校内 GPU + 一堆外部站，但**排产决策靠印象**，
结果：GPU 排队浪费、有的实验跑 62 天才发现超预算。

### 你已经踩过的坑（都在 memory 里，别重犯）

| 坑 | 正确规则 |
|---|---|
| 62 天实验 | **每实验 ≤ 72h**；测速必须**在目标配置上实测**（U8→U32 差 23.6 倍） |
| 误判 GPU 空闲 | **准入只看 used/free 显存，util 不作门槛** |
| 占位/无效实验 | 禁占位；每臂必须有可判定的成功判据 |
| 跨机移植步时 | **步时不可跨臂跨机移植**（差 34 倍） |

### 解法：**一张表决定"现在能不能起这个实验"**

```bash
# 起任何训练前，先跑这两道闸
python ops72.py <PLAN.json>        # 72h 预算闸（实测 < 72h 才放行）
python ops72.py --measure <steps.jsonl>   # 先测步时中位数
pwsh -File "<ops>/farm-status.ps1" -Json    # 三机显存
```

> **`ops72.py` 的真实接口**（别记错）：
> - `ops72.py <PLAN.json>` —— 读 plan 里的 `full_steps` /
>   `measured_seconds_per_step` / `measured_n_samples`，算 `小时 × 1.25` 是否 ≤ 72h。
>   **没有 `measured_seconds_per_step` 它会直接拒绝，不猜。**
> - `ops72.py --measure <steps.jsonl>` —— 从真实记录的 step 日志算**中位数**步时。
> - 脚本内建的安全系数：**×1.25**（实测 wall clock 比记录值慢 24%），
>   **最少 100 个记录样本**（`native8` 的步时会虚高 18 倍，必须禁用）。
> - 本机副本：
>   `C:\Users\18798\Documents\RectSSL_Artifacts\20261020_claim_code_effect_audit_155740\corpus\cfe75f97c6f0\ops72.py`
>   （正式副本已部署到三台校内机）。

**只有两个都过才起**：
1. `ops72.py` 判定 PASS（且测速是在**那个配置**上跑的，不是别的臂的）
2. `farm-status.ps1` 显示有足够 free 显存

> ⭐ **为什么这条排在"综合能力"里而不是"科研技巧"里**：
> 你不是不会做研究，是**研究的速度和调度**在拖累你。
> 这条线的收益是**倍数级**的，其他线是加法。

### 手上要做的
把 `ops72.py` 的输出接进你的"起实验"检查清单，
并**在实验 README 里贴一行预估耗时**（事后能对账）。

## 能力线 6 · 边界与安全（AI 编程时代的新基本功）

### 你的机器上有真实的 token、API key、和别人的服务器

**必须守住的四条**（按你实际踩过的坑排序）：

| # | 规则 | 你的具体证据 |
|---|---|---|
| 1 | **凭据不进仓库、不进新文件、不进日志** | `agentrouter.credentials.json`、`.env` 里的真 key；写脚本时只引用环境变量名 |
| 2 | **共享服务器只读别人的资源** | `ops/README.md` 的 `no_scheduled_automation=true`；不 kill、不改、不读别人私有日志 |
| 3 | **AI 不代替人做不可逆决定** | 合并权在人手里；停止在跑实验只在明确指令后 |
| 4 | **数字必须带出处标签** | 轮次/父点/`test-informed`/`oracle`；不写"必达/显著/SOTA" |

### 补一条 AI 时代特有的
**5 · agent 写的代码进仓库前必须过闸**（能力线 1）。
AI 会写出"看起来对但编译不过/逻辑错/用了错 API"的代码。
**闸比 review 便宜。**
