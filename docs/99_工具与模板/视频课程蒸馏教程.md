# 视频课程蒸馏教程（B站 + 百度网盘本地文件）

> **核心结论先说**：**你不需要自己写转写脚本。**
> DeepTutor 已经内置了三条视频入口，本机 `deeptutor` 容器**全都已经装好**：
>
> | 视频来源 | DeepTutor 怎么接 | 需要额外装什么 |
> |---|---|---|
> | **B站**（在线） | 原生 `BilibiliLoader` → 官方 `player/v2` 接口取字幕（含 AI 字幕）→ 时间轴对齐 | **什么都不用装** |
> | **YouTube**（在线） | `youtube-transcript-api` → `.vtt` → 时间轴 | **什么都不用装** |
> | **百度网盘下载的本地文件** | ffmpeg 切片 → STT 转写 → 时间轴 | **要配一个 STT**（见 §3） |
>
> 依据：本机容器实测（2026-11-11），代码在
> `deeptutor/reading/ingestion.py`。

---

## 0. 为什么走 DeepTutor 而不是自己搞

自己搞视频蒸馏要处理：下载 → 提音轨 → 转写 → 对齐时间轴 → 切片 → 塞进 RAG → 生成讲义。
DeepTutor 已经把这六步做完了，而且**B站是原生支持**的：

```
docker exec deeptutor grep -n 'BilibiliLoader' .../deeptutor/reading/ingestion.py
```

它的取字幕路径（实测代码）：

```
GET https://api.bilibili.com/x/web-interface/view?bvid=...   # 标题/时长/分P
GET https://api.bilibili.com/x/player/v2?bvid=...&cid=...      # 字幕 + view_points 章节
   → subtitle.subtitles[]        # 官方字幕 + AI 字幕
   → view_points[]               # 视频的章节点
   → build_transcript_segments() # 生成带时间戳的转写段
```

**注意最后一行：它走的是 B站官方接口，不是下载视频。**
所以 B站这条路**不消耗你的带宽，也不占硬盘**，秒级拿到带时间轴的字幕。

## 2. 路线 A · B站在线视频（最省事，零配置）

### 2.1 在 DeepTutor 里怎么用

```
1. 打开 http://127.0.0.1:3782
2. 新建一个工作区（Workspace），名字按主题，比如 "C语言-指针"
3. 进「阅读 / Reading」能力  →  添加材料 → 选「视频」
4. 粘 B站链接：
   https://www.bilibili.com/video/BV1Jync69EKu
   （多 P 视频可以指定 ?p=2）
5. 它会：
   - 取标题/时长/UP主/分P
   - 取字幕（优先官方字幕，没有就用 AI 字幕）
   - 按 view_points 生成章节
   - 生成带时间戳的转写段
6. 转写完成后，这个视频就进了该工作区的知识库
7. 之后用 Chat / Quiz / Research / Mastery Path / 沉浸式看片 都能用这份材料
```

**关键**：字幕转写完成后，**视频材料本身是可检索、可问答、可出题的知识库条目**，
这正是"蒸馏"要的东西。

### 2.2 批量灌进去（配合已有采集器）

已有脚本能批量搜 B站、拿到权威标题和发布日期。批量导入的顺序：

```

        → 输出 Markdown 清单（含 BV 号）
② 筛选：  人工/脚本挑你要的，把 BV 号写进一个列表文件
③ 灌入：  在 DeepTutor 的阅读能力里逐个添加（或用 API 批量）
④ 蒸馏：  对着知识库跑 Quiz / Mastery Path，产出讲义与练习
```

## 3. 路线 B · 百度网盘下载的本地文件（要配一个 STT）

### 3.1 它是怎么工作的（实测代码）

```
_d_chunk_media_audio(path)
    ├─ 检查 ffmpeg 在不在（容器里有）
    ├─ ffmpeg -i <video> -vn -ac 1 -ar 16000 -f mp3  → 切成 16k 单声道 mp3 分片
    └─ 每个分片交给 STT → 转写成 cue → _rebase_cues 还原时间轴
```

关键错误码（容器实测）：

| 错误码 | 含义 | 怎么办 |
|---|---|---|
| `stt_not_configured` | **没有配置语音转文字模型** | 见 §3.2 |
| `media_transcription_failed` | 转写过程出错（网络/格式/文件损坏） | 看日志 |
| `Video transcription requires ffmpeg` | 容器里没 ffmpeg | 你这里没有（已装） |

> 💡 **它很贴心地先问"有没有 STT"再动 ffmpeg** ——
> 没有的话不会白烧 CPU，直接报 `stt_not_configured` 并告诉你缺什么。

### 3.2 配 STT（你只差这一步）

**入口**：DeepTutor 界面 → **Settings → Voice**（语音）

底层是 `resolve_stt_runtime_config()`，它做三件事：

```
1. 从模型目录（model_catalog.json）里取"当前激活的 STT 模型"
   → 没配就抛错："No active STT model is configured. Set it in Settings > Voice."
2. provider 从 STT_PROVIDERS 里查规格（默认 base_url / 适配器 / 鉴权风格）
3. 本地 provider 没 api_key 时自动填 "sk-no-key-required"
```

**所以：Settings → Voice 里加一个 STT 模型就行。**

#### DeepTutor 内置的 STT provider（实测读源码得到）

容器里 `deeptutor/services/config/provider_runtime.py` 的 `STT_PROVIDERS` 表：

| provider | 界面名 | 默认 base_url | 默认模型 | 本地? |
|---|---|---|---|---|
| `volcengine_speech` | Volcengine Speech (Doubao) | `https://openspeech.bytedance.com/api/v3` | `bigmodel` | 否 |
| `dashscope` | Aliyun DashScope | `https://dashscope.aliyuncs.com/api/v1` | `paraformer-realtime-v2` | 否 |
| `openai` | OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini-transcribe` | 否 |
| `openrouter` | OpenRouter | `https://openrouter.ai/api/v1` | `openai/whisper-large-v3` | 否 |
| `groq` | Groq | `https://api.groq.com/openai/v1` | `whisper-large-v3-turbo` | 否 |
| `siliconflow` | SiliconFlow | `https://api.siliconflow.cn/v1` | `FunAudioLLM/SenseVoiceSmall` | 否 |
| `azure_openai` | Azure OpenAI | （自填） | `whisper-1` | 否 |
| `vllm` | vLLM | `http://localhost:8000/v1` | （自填） | **是** |
| `custom` | **OpenAI Compatible** | （自填） | （自填） | 否 |

> `custom` 的 label 就是 **"OpenAI Compatible"** —— 意味着**任何 OpenAI 兼容的
> `/audio/transcriptions` 端点都能接**。

#### ⚠️ 实测：你的两个中转站**不能**当 ASR 后端

我用 1 秒生成音调（无任何私人内容）实测了两个站：

```
pincar      https://intl.freehyy.com      whisper-1 → 403   gpt-4o-mini-transcribe → 403
agentrouter https://agentrouter.org/v1     whisper-1 → 401   gpt-4o-mini-transcribe → 401
```

403/401 都是**那两个站的"只认官方 Codex 客户端"校验**（和之前测到的
`This account only allows Codex official clients` / `unauthorized client detected` 同源），
**不是"没有 ASR 端点"的结论** —— 换句话说**用普通客户端无法判定**。
但既然普通客户端根本进不去，**这条路实际不可用**。

#### 三个可行方案

| 方案 | 怎么配 | 成本 | 质量 |
|---|---|---|---|
| **① SiliconFlow**（推荐，中文好、便宜） | Settings → Voice → provider 选 `siliconflow`，base_url `https://api.siliconflow.cn/v1`，模型 `FunAudioLLM/SenseVoiceSmall` | 很便宜 | 好（SenseVoice 对中文强） |
| **② Groq** | provider 选 `groq`，base_url `https://api.groq.com/openai/v1`，模型 `whisper-large-v3-turbo` | 免费层够用 | 很好 |
| **③ 本机 vLLM**（完全离线） | provider 选 `vllm`，base_url 指向本机 `http://host.docker.internal:8000/v1`，起一个 whisper/vllm 服务 | **0** | 好；3060 12GB 跑 large-v3 int8 没问题 |

#### ⚠️ 实测修正：OpenRouter 那条默认值现在是坏的

DeepTutor 里 `openrouter` 的默认模型是 `openai/whisper-large-v3`，
但我查了 OpenRouter 现在的目录（469 个模型）：

```
openai/whisper-large-v3   in catalogue: False
openai/whisper-1           in catalogue: False
```

**这个模型 id 已经不在目录里了** —— 直接用默认值会失败。

而且 OpenRouter 的 `/audio/transcriptions` 只对**特定**模型开放，
目录里标了 `input_modalities` 含 `audio` 的共 48 个，但绝大多数是
**多模态对话模型**（gemini-4-carbon / qwen3.8-omni / muse-ember …），
不是专用转写模型。

**唯一免费且接受音频的**：`nvidia/nemotron-3-nano-omni-30b-a3b-reasoning:free`
—— 但那是推理模型，**不是 Whisper 系**，DeepTutor 的 `openai_compat` 适配器
能不能正确处理它的输出**未经验证**，不建议作为第一条路。

👉 **结论：优先试 ① SiliconFlow（中文课程最对口），其次 ② Groq，
最稳的是 ③ 本机跑（免费且可控）。**

#### 端点可达性（我实测过，2026-11-11）

```
siliconflow  /models -> HTTP 401  (可达，需要 key)
groq         /models -> HTTP 403  (可达，需要 key)
openrouter   /models -> HTTP 200  (可达)
openai       /models -> HTTP 401  (可达，需要 key)
```

**四个都不需要"翻墙才能连"的问题 —— 都可达，只是要 key。**

> ⚠️ **注意**：你本机 Ollama 里只有 `qwen3` / `qwen2.5` / `bge-m3` / `nomic-embed-text`
> —— **这些都是对话/嵌入模型，不是 ASR**。做转写要用 Whisper 系或云端 ASR。
> 容器里也**没有** whisper / faster-whisper（实测 `find_spec` = False）。
>
> 💡 若选方案③，容器里访问宿主机要用 `host.docker.internal`
> （官方 compose 文档明确写了这点），不是 `localhost`。

#### 走云端最快（推荐你这么做）

你的中转站 **agentrouter / pincar 都是 OpenAI 兼容的**（`/v1`），
它们是否提供 ASR 端点需要试。若提供，在 Settings → Voice 里：

```
provider : OpenAI-compatible (或 Whisper)
base_url : https://agentrouter.org/v1
api_key  : 你的 agentrouter key
model    : 对方给的 ASR 模型名（如 whisper-1）
```

**这也正好回答了"利用 API 和本地资源"** ——
用中转站的 ASR 额度转写本机下载的视频，**课也不花钱**。

### 3.3 本地文件放哪、怎么导入

```
① 把网盘下载的视频放到：
   D:\DeepTutorLab\data\user\workspace\     ← 容器挂载为 /workspace
   
② DeepTutor 里「添加材料」→ 上传/挂载该文件
   （支持 .mp4/.mkv/.mov/.webm 等视频，音频 .mp3/.m4a/.wav/.aac/.ogg/.flac 也行）
   
③ 它自动：ffmpeg 切片 → STT → 时间轴 → 进知识库
```

**注意 `DEEPTUTOR_WORKSPACE_ROOT=/workspace` + `DEEPTUTOR_WORKSPACE_ALLOWED_ROOTS=/workspace`**
—— 容器里模型只能碰 `/workspace`，所以**文件必须放在这个目录里**，
放别处会读不到。这也是那个隔离设置的本意（防止模型生成的代码乱删你的东西）。

### 3.4 ⚠️ 一个必须知道的限制

```
chat_attachment_max_file_mb   : 20
chat_attachment_max_total_mb  : 25
```

**聊天附件上限 20MB/个、25MB/总量。**
一个 1 小时的课程视频通常 200MB~2GB —— **不能走"聊天附件"这条路**，
必须走"知识库材料"那条路（那个不受 20MB 限制）。

## 5. 完整工作流（一条线）

```
① 找素材
   B站： .\collect-videos-bili.ps1 -Query "C语言 指针" -MinDate 2024-01-01 -Max 15
   本地： 网盘下载 → 放进 D:\DeepTutorLab\data\user\workspace\

⑤ 落成本地课程包
   把 Quiz/Mastery Path 的结果导出，按「技术蒸馏课程」的结构拆成
   00_导读 / 10_要点 / 20_动手 / 30_自测 / 99_复盘

⑥ 过质量闸
   python 技术蒸馏课程\99_工具与模板\verify.py <课.md>
   （本地 gcc 编译所有代码块，不消耗任何额度）
```
