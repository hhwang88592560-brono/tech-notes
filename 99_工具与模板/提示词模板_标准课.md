## 你的任务

把上面「本课主题」蒸馏成一份**可执行的学习包**。严格按下面的结构输出，
五个部分都要有，用 `##` 作为二级标题分隔。

### 00_导读
- 这课要解决什么具体问题（不要写"学习指针"这种废话，要写"为什么你的程序跑飞了"）
- 学完能做出什么（可验证的动作，不是"理解"）
- 需要哪些前置知识
- 预计耗时

### 10_要点
- 核心概念，每个 2~4 句讲清，**先讲"是什么"再讲"为什么这样设计"**
- **常见坑**：至少 3 条，每条写清楚「错误写法 / 后果 / 正确写法」
- 关键 API、寄存器、标准：每条注明**出处**（标准号/手册章节/权威链接）
- 有争议或容易记错的地方，明确标注"这一点很多教程写错了"

### 20_动手
- 2~4 个实验，**从最小可运行到渐近复杂**
- 每个实验给：目标 / 完整代码 / 预期输出 / 怎么验证
- 代码必须是**能编译运行的**，不要用伪代码，不要用 `...` 省略
- 嵌入式相关：注明目标平台（假设 Cortex-M / STM32F1，明确说出假设）
- 涉及中断/寄存器的地方，标注哪些访问必须加 `volatile`

### 30_自测
- 8~12 题，分三档：概念题 / 代码找错题 / 设计题
- **每题单独给参考答案**，答案放在题后用 `> 参考答案：` 引用块
- 代码找错题必须是**真的会编译通过但行为错误**的代码，不要写语法错误
- 设计题要给出评分要点

## 硬性要求

1. **不要输出课程范围之外的内容。** 我问指针，就不要顺带讲网络编程。
2. **代码必须完整可编译。** 不要写 `// ... 其余代码不变`。
3. **不确定的API/寄存器名，标注"需查手册确认"，不要编。**
   编造一个看起来很像的寄存器名，比留空更有害。
4. **区分"标准规定"和"某平台实现"。** 比如 `int` 的大小是实现定义的。
5. **中文正文，代码注释也用中文**，但标识符用英文。
6. **不要复述我的提问**，直接给内容。
